================================================================================
TGDesk - ANALISE DE PONTOS DE ENTRADA E ARQUITETURA
================================================================================

1. PONTOS DE ENTRADA (Entry Points)
================================================================================

1.1 SERVER - api-core (Go)
   Arquivo: server/api-core/cmd/main.go
   Função: main()

   Sequência de boot:
   1. Load config from env vars (DATABASE_URL, REDIS_ADDR, JWT_SECRET, etc)
   2. Connect to PostgreSQL (pgx pool)
   3. Run DB migrations from server/migrations/ (25 migrations, lexical order)
   4. Connect to Redis
   5. Run seed (demo data + technician assignments)
   6. Start WireGuard Hub (startHub) se HUB_LISTEN_PORT configurado
      - Load/generate keypair from HUB_KEY_FILE
      - Restore persistent peers from DB (devices + technicians com WG keys)
   7. Create HTTP router + middleware (CORS, JWT, VPN-only, super-admin checks)
   8. Listen on LISTEN_ADDR (default :8080)

   Dependências: PostgreSQL, Redis, WireGuard userspace, config env vars

1.2 SERVER - hbbs (RustDesk Rendezvous Server)
   Arquivo: server/rustdesk-server-src/src/main.rs
   Função: main() -> ResultType<()>

   Sequência de boot:
   1. Initialize logger (flexi_logger, env/str config)
   2. Parse CLI args: --config, --port(3001), --serial, --rendezvous-servers, etc
   3. Start RendezvousServer::start() async

   Responsabilidade: ID server + rendezvous (peer discovery, NAT traversal hints)

1.3 CLIENT - client-host (Go - Agente mínimo Fase 1)
   Arquivo: client-host/main.go
   Função: main()

   Sequência de boot:
   1. Load config from disk (tgdesk-agent.json) ou register novo
   2. Device registration (POST /api/v1/devices/register) se novo
   3. Exibir pairing code ao usuário
   4. Loop de heartbeat a cada 5s:
      - POST /api/v1/devices/heartbeat (device_id, device_token)
      - Recebe state: "guest" | "ativo" | "suspenso"
   5. Se ativo:
      - Check UAC elevation
      - bringUpTunnel(): gera WG keypair, POST WG key, ativa adaptador "tgdesk0"
      - setupRemoteAccess(): integra RustDesk
      - reportTelemetry(): CPU, memória, discos (30s interval)

   Arquivo config: tgdesk-agent.json (device_id, device_token, wg_private_key, virtual_ip)

1.4 CLIENT - client-tunnel (Go - Técnico VPN)
   Arquivo: client-tunnel/main.go
   Função: main()

   Sequência de boot:
   1. Parse --server, --token (JWT do técnico logado)
   2. Load config (tgdesk-tunnel-config.json) ou gerar nova chave WG
   3. POST /api/v1/technicians/wg-key (token, public_key)
   4. Recebe VirtualIP, HubPublicKey, HubEndpoint, RendezvousHost, etc
   5. Criar adaptador "tgdesk-tech0", config WG via netsh interface ip set address
   6. Seleciona {} // mantém processo vivo, o Hub o encerra junto

   Responsabilidade: Túnel WireGuard individual pro técnico (independente do host na mesma máquina)

1.5 CLIENT - client-updater (Go - Bootstrapper)
   Arquivo: client-updater/main.go
   Função: main()

   Responsabilidade: Mínima - embed tgdesk-installer.exe, extract, launch elevated (UAC)

1.6 CLIENT - RustDesk Core (Rust - Desktop/Mobile)
   Arquivo: client-rustdesk-src/src/main.rs
   Função: main() (condicional por platform)

   Multi-plataforma:
   - Android/iOS/Flutter: Minimal - common::global_init(), test_rendezvous, test_nat_type, global_clean()
   - Desktop (Windows/Linux/macOS): DPI awareness, core_main::core_main(), ui::start()

   Módulos via lib.rs:
   - client: remote session state machine
   - server: RDP listener (recebe conexões de técnicos)
   - common: config, logger, rendezvous client, protobuf messages
   - platform: Windows/Linux/macOS specific (clipboard, input, screenshot)
   - hbbs_http: HTTP client para API (account, download, sync, record upload)
   - plugin: native plugin framework (callbacks, UI extensions)
   - ipc: inter-process comm (auth, filesystem)

1.7 CLIENT - Flutter UI (Dart)
   Arquivo: client-rustdesk-src/flutter/lib/main.dart
   Função: main(List<String> args)

   Sequência de boot:
   1. earlyAssert(), WidgetsFlutterBinding.ensureInitialized()
   2. Parse boot args (kWindowId, multi_window mode, window type)
   3. Decidir: mobile (runMobileApp) vs desktop (multi-window)
   4. Desktop: switch WindowType:
      - RemoteDesktop -> runMultiWindow(argument, kAppTypeDesktopRemote)
      - FileTransfer -> runMultiWindow(argument, kAppTypeDesktopFileTransfer)
      - ViewCamera, PortForward, Terminal, etc
   5. Provider + GetX para state management

   Telas: install_page, server_page, remote_screen, file_transfer_screen, etc

3. FLUXO DE INICIALIZACAO
================================================================================

3.1 SERVIDOR (api-core)

   1. Config Load (env vars)
   2. DB Connect + Migrate
   3. Redis Connect
   4. Seed demo data (if enabled)
   5. StartHub (WireGuard orchestrator)
      - Load persistent peers from DB
   6. Create HTTP router (80+ endpoints)
   7. ListenAndServe(:8080)

3.2 DEVICE (client-host)

   1. Load config ou RegisterDevice (POST /api/v1/devices/register)
      -> recebe device_id, pairing_code, device_token
   2. Exibir pairing code ao usuário
   3. Loop: Heartbeat (5s interval)
      - POST /api/v1/devices/heartbeat (device_id, device_token)
      - Recebe state: guest | ativo | suspenso
   4. Transição ativo:
      a. Check UAC elevation (Windows only)
      b. BringUpTunnel
         - Gerar WG keypair (ou load existing)
         - POST /api/v1/devices/wg-key (device_id, device_token, pub_key)
         - Recebe VirtualIP, HubPublicKey, HubEndpoint
         - Create TUN "tgdesk0"
         - Configure WG peer (hub public key, allowed IPs 10.70.0.0/16)
         - IPC set + device up
         - Assign IP via netsh
      c. SetupRemoteAccess (RustDesk integration)
         - Start RD server listener
      d. ReportTelemetry (30s interval)

3.3 TECHNICIAN (client-tunnel)

   1. Parse --token (JWT do login no Hub)
   2. Load config (WG private key) ou gerar novo
   3. POST /api/v1/technicians/wg-key (token, wg_public_key)
      -> recebe VirtualIP, HubPublicKey, HubEndpoint, RendezvousHost, etc
   4. Create TUN "tgdesk-tech0"
   5. Configure WG peer
   6. Assign IP via netsh
   7. Seleciona {} // daemon mode

7. ARQUITETURA DE REDE (WireGuard Hub)
================================================================================

Hub Mode:
- Interface: wg0 (Linux) ou tgdesk0 (Clientes)
- CIDR: 10.70.0.1/16 (hub), 10.70.0.0/16 (range para peers)
- Spoke topology: Cada device/technician = peer, hub = central relay
- Keepalive: 25s (persistent_keepalive_interval)
- Allowed IPs: 10.70.0.0/16 para todos (full mesh capability)

Device WireGuard enrollment:
1. Device gera keypair
2. POST /api/v1/devices/wg-key (device_id, device_token, pub_key)
3. API-Core:
   - Valida device
   - Gera virtual IP do range 10.70.x.x/32
   - AddPeer(pubkey, virtual_ip) -> hub.dev.IpcSet()
   - Retorna: VirtualIP, HubPublicKey, HubEndpoint, RendezvousHost
4. Device:
   - Cria TUN device
   - Configure peer (hub pub key, endpoint, allowed IPs)
   - Assign IP
   - IPC up
   -> Conectado à VPN central

Technician WireGuard enrollment:
- Similar ao device, mas
- POST /api/v1/technicians/wg-key (JWT token, wg_public_key)
- Cada technician = peer independente, permite múltiplas maquinas (Seção 7.A)

Cascade de restauração na startup:
- Query: SELECT wg_pubkey, wg_virtual_ip FROM devices WHERE state='ativo' AND wg_pubkey<>''
- Query: SELECT wg_pubkey, wg_virtual_ip FROM technicians WHERE status='ativo' AND wg_pubkey<>''
- hub.AddPeer(pubkey, virtual_ip) para cada um -> restaura malha


8. AUTENTICACAO E AUTORIZACAO
================================================================================

8.1 JWT (Technician authentication)

   Claims (auth/auth.go):
   {
     "tid": "technician_id",
     "username": "...",
     "role": "super_admin | tecnico | freelancer",
     "exp": now+12h,
     "iat": now
   }

   Signing: HS256 (JWT_SECRET env var)
   Issuance: POST /api/v1/auth/technician/redeem (enrollment key) ou seed

   Token lifetime: 12 hours
   Refresh: POST /api/v1/auth/technician/refresh -> new JWT

8.2 Device Token

   Generado na registration (RegisterDevice)
   Usado para: heartbeat, WG key submission, telemetry
   Não relacionado a JWT

8.3 RBAC (technician_assignments)

   Role:
   - super_admin: full access (orgs, techs, audit, suspend/resume)
   - tecnico: limited to assigned org/network (RBAC aplicado em handlers)
   - freelancer: support tickets only

   Assignment scope (technician_assignments):
   - (technician, org=null, network=null) = all devices in all orgs
   - (technician, org=X, network=null) = all devices in org X
   - (technician, org=X, network=Y) = devices in network Y of org X

   Filtering: handlers checam claims.TechnicianID vs assignment rows

8.4 VPN Requirement

   Middleware (middleware/middleware.go):
   - private() middleware: requestFromVPN(r) checks se origin IP está em 10.70.0.0/16
   - Protege: device operations, presence WS, network CRUD, etc
   - Exceção: public endpoints (register, heartbeat, client updates)

8.5 Password Hashing

   Algoritmo: bcrypt (cost=default)
   Funções: HashPassword(), CheckPassword()
   Armazenado em: technicians.password_hash

10. RESUMO EXECUTIVO
================================================================================

COMPONENTES PRINCIPAIS:
1. Server (api-core): API REST + WebSocket, PostgreSQL backend, Redis cache, WireGuard hub
2. Device agent (client-host): Registro, heartbeat, WG tunnel, telemetry, RustDesk integration
3. Technician VPN (client-tunnel): WG peer for individual tech tunnel
4. RustDesk client (client-rustdesk-src): Remote desktop, file transfer, port forward, etc
5. Flutter UI (client-rustdesk-src/flutter): Cross-platform UI (Windows, Linux, macOS, mobile)

FLUXO PRINCIPAL (Fase 1):
1. Device instala agent, registra em API, exibe pairing code
2. Técnico valida código, bind device via API
3. Device recebe state='ativo', ativa WG tunnel
4. Técnico ativa tunnel (client-tunnel)
5. Ambos online na VPN 10.70.0.0/16, pronto para RDP/file transfer

TECNOLOGIAS:
- Backend: Go, PostgreSQL, Redis, WireGuard, HTTP/REST, WebSocket
- Desktop Client: Rust (RustDesk core), Flutter (UI), Dart
- Network: WireGuard spoke topology, 10.70.0.0/16 CIDR, rendezvous + relay
- Auth: JWT HS256, bcrypt, VPN-based access control, RBAC via assignments
